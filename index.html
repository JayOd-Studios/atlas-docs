Deploy your first app

One command ships a build to the region you name, then keeps the previous release live until traffic moves. This guide takes about four minutes from an empty directory.

Before you start. You need an Atlas account, a project directory with a build script, and Node 20 or newer. Nothing else — no Docker, no config file.

Prerequisites

  • Node.js 20 or later — node --version should print v20 or higher.
  • A project with a build script. Atlas runs it, then uploads the output directory.
  • An API token: atlas login stores one in your keychain.

Run the deploy

From the project root, name the region you want traffic served from. Atlas uses the nearest region by default if you leave it out.

  1. Authenticate once

    shell
    atlas login

  2. Deploy

    shell
    atlas deploy --region "eu-west" --prod

    Add --dry-run to print the change set without shipping it. The flag is safe to use in CI.

  3. Watch traffic move

    Atlas keeps the previous release at 100% until the new one passes its readiness check, then moves it over in under ten seconds. The old release stays addressable for rollback.

Flags

FlagTypeDefaultWhat it does
--regionstringnearestRegion that serves the deployment.
--prodbooleanfalsePromotes the release to production traffic.
--dry-runbooleanfalsePrints the change set and exits.
--envstringproductionEnvironment name for scoped variables.

Verify the deployment

A successful deploy prints the release ID and the URL. Check the release is live before you point a domain at it:

shell
atlas releases list --limit 3

# RELEASE   REGION    STATUS     CREATED
rel_8f21c   eu-west   live       12s ago
rel_71ba0   eu-west   retired    6m ago

That is it. The next guide covers environment variables, previews and rollbacks. If a deploy fails, the error page lists every exit code and what to do about it.

Install the CLI

The Atlas CLI is one binary with no runtime dependencies. Install it with the package manager you already use, or download a signed build.

Install with a package manager

npm install --global @atlas/clipnpm add --global @atlas/clibun add --global @atlas/cli

Requirements

ItemMinimumNotes
Node.js20Only needed for project builds, not the CLI itself.
macOS13Apple silicon and Intel builds.
Linuxglibc 2.31x86_64 and arm64.
Windows10WSL2 recommended for build scripts.

Verify the install

shell
atlas --version
# 2.4.1

Command not found? The global bin directory may not be on your PATH. Run npm bin -g and add the printed path to your shell profile, then open a new terminal.

Docs / API reference

Errors

Every failed request returns a JSON body with a code, a message and a request ID. Fix the cause using the table below; quote the request ID if you open a support ticket.

The error body

json
{
  "error": {
    "code": "ATL-422",
    "message": "No build output found at dist/.",
    "requestId": "req_9c41d2"
  }
}

Error codes

CodeMeansFix
ATL-401Missing or expired token.Run atlas login again. Tokens last 30 days.
ATL-409A deploy is already in progress.Wait for it to finish, or pass --force to supersede it.
ATL-422The build output directory is missing or empty.Check the build script, and that dist/ exists after it runs.
ATL-429Rate limit reached.Back off using the Retry-After header. Limit is 60 deploys an hour.
ATL-503Region unavailable.Retry once, then deploy to another region.

CLI exit codes

Scripts can branch on these without parsing output:

ExitMeaning
0Success — release is live.
1Build failed. Read the build log, not the JSON body.
2Invalid flags or missing config.
3Authentication failure.

A note on retries. Retry only ATL-503 and ATL-429, and only with a fresh request ID. Retrying a ATL-422 just burns your rate limit — the build output will still be missing.
